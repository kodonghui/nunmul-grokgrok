# 알림 표정 이미지 · SPEC-NOTIFY-IMAGE-001

사용자 요청(2026-11-01, 이 Codex 대화): “알림에 우는·웃는 이미지 붙이는 것부터 구현해줘. 책상친구는 건드리지 말고, 테스트 통과하면 main에 푸시하고 그록한테 보낼 프롬프트도 줘.”

## 범위와 출력

- Grok이 채팅에 첨부할 공개 PNG 네 장과 검증한 파일 경로를 제공한다. 앱 프로필 사진 자동 교체·울음 음성·애니메이션·책상친구는 범위가 아니다. 기존 원장 스키마·재촉 시각·대상 선택·Calendar 반영 규칙은 유지한다.
- `dose_state.py due/mark --with-images`, `intake.py confirm --with-images`에서만 이미지 메타데이터를 추가한다. 옵션 없는 기존 출력과 순수 함수는 호환을 유지한다. 실제 이미지 전송은 Grok이 수행하며 Python이 보냈다고 보고하지 않는다.
- `due`는 복용 회차의 재촉1/2/3단계에 각각 글썽/한 방울/두 방울 이미지를 `send[].image`로 붙인다. 재방문·병원 방문·MISSED 종료 알림에는 붙이지 않는다. 빈 send·조용한 시간·이미 확인/중단/삭제된 회차는 기존대로 조용히 끝난다.
- `mark`는 채팅 출처로 새 복용 확인을 기록하고 해당 활성 회차 전체가 TAKEN일 때만 최상위 `image`에 미소를 붙인다. 일부 약만 확인한 결과·SKIPPED가 섞인 회차·대상 없음·재실행·desk 출처에는 미소를 붙이지 않는다. 오류나 저장 실패에서도 미소 결과는 반환하지 않는다.
- `intake.py propose`에는 이미지를 붙이지 않는다. dose.mark 확정의 최초 성공에만 위 미소 규칙을 적용하며 COMMITTED 초안 재실행에는 이미지가 없다. 공개 이미지 경로는 원장·초안 결과에 저장하지 않고 반환 결과에서만 파생한다.
- `image`는 `{id, path, mimeType, alt, sha256}`다. path는 현재 체크아웃의 절대 경로, mimeType은 image/png다. 이미지에는 약 이름·프로필 ID·복용 기록·비밀값이 없다. Grok은 이 파일을 첨부하고 alt를 첨부 성공의 증거로 대신하지 않는다.

## 파일과 실패 처리

- `assets/notifications/`에 선택한 공개 이미지 사본만 넣고 원본 마스코트는 변경하지 않는다. `config/notification_images.json`의 고정 네 항목·경로·PNG 형식·크기·SHA256을 명령 실행 전에 검증한다.
- 누락·손상·경로 이탈은 `INVALID_IMAGE_ASSET`로 실패하며, due의 발송 단계나 mark의 복용 기록을 소비하지 않는다. 검증 오류 메시지에는 파일 본문이나 사용자 입력을 반사하지 않는다.
- `python3 tools/notification_images.py`는 원장·네트워크를 사용하지 않고 이미지 네 장의 첨부 정보를 확인한다. 실행 환경에는 추가 Python 패키지나 실제 키가 필요 없다.
- 재촉은 기존 sentStep의 중복 방지 규칙을 따른다. 이미지 전송 실패를 복구하려고 due/mark를 다시 실행하지 않는다. 최초 결과를 보관하고 그 결과의 파일을 다시 첨부한다. 기존 구조에는 채팅 전달 성공을 확인하는 영속 outbox가 없으며 이미지 전송 완료를 보장한다고 말하지 않는다.

## 검증 기준

합성 원장/fixtures만 사용해 세 재촉 단계, 같은 now 재실행, 야간·MISSED·방문/재방문, 가족 격리, 일부/전체 복용 확인, mark 재실행, intake 초안/확정/재실행, 자산 오류와 원자적 저장 실패를 검사한다. 기존 테스트를 모두 실행한다. 실제 Grok 채팅에서 PNG 첨부가 표시되는지는 인계 프롬프트로 별도 확인하며 단위 테스트로 대체하지 않는다.
