# SPEC-NOTIFY-IMAGE-001 · 채팅 표정 이미지 검증

근거: 사용자가 2026-11-01 이 Codex 대화에서 “알림에 우는·웃는 이미지 붙이는 것부터 구현해줘. 책상친구는 건드리지 말고, 테스트 통과하면 main에 푸시하고 그록한테 보낼 프롬프트도 줘.”라고 요청했다. 계약은 [알림 이미지 명세](notification-images.md), 운영 인계는 [전체 적용 프롬프트](grok-bot-notification-images-setup.md)다.

## 변경과 이유

기존 도구는 알림 문구만 반환했다. 공개 PNG 네 장과 고정 매니페스트를 저장소에 포함하고 `--with-images`에서만 실제 첨부용 파일 정보를 반환한다. 재촉 1·2·3단계는 글썽·한 방울·두 방울이며, 채팅에서 새로 기록한 해당 활성 회차의 약 전체가 TAKEN일 때 미소를 반환한다. 원장·초안 결과에는 파일 경로를 저장하지 않는다. 실제 채팅 첨부는 Grok이 맡는다.

## 직접 확인한 결과

- Windows `py -m unittest tests.test_notification_images`: 추가 20개 모두 통과. 첫 실행에서는 합성 v1 일정과 가족 원장을 같은 임시 폴더에 둬 기존 이관 충돌 검사가 작동했다. 시험 폴더를 분리했고 운영 이관 규칙은 바꾸지 않았다.
- 최종 Windows `py -m unittest`: 263개, 18.371초, 실패 0·오류 0·건너뜀 1. 기존 243개에 20개를 추가했다. 실제 POSIX 접근 권한 검사 1개는 Windows에서 기존대로 건너뛴다.
- 모든 새 시험은 임시 디렉터리·합성 프로필/약·fixture만 사용한다. 네트워크 접근을 막았으며 실제 키나 공공데이터 서비스를 쓰지 않았다. 별도 프로세스의 `-S -B` 실행으로 추가 패키지 없이 JSON 한 덩어리를 반환하는 것도 확인했다.
- 세 재촉 단계의 이미지 선택, 같은 시각 재호출 무발송, 늦은 첫 순찰의 현재 단계 선택, 야간·지난 등록 전 회차의 무발송, MISSED·방문/재방문의 텍스트 전용 동작을 검증했다.
- 가족별 회차 분리, 한 약만 확인할 때 미소 없음, 마지막 약을 새로 확인할 때 미소 한 번, 이미 확인한 mark/confirm 재실행의 미소 없음, SKIPPED 혼합 회차·대상 없음·desk 출처의 미소 없음을 검증했다.
- 중단·삭제한 약에는 이미지 알림이 없고 다른 가족의 알림은 유지됐다. intake 초안은 TAKEN이나 미소를 만들지 않았고 확정의 최초 성공만 미소를 반환했다. 저장된 초안 결과에는 image가 없었다.
- 누락 파일·손상 PNG·매니페스트 경로 이탈은 `INVALID_IMAGE_ASSET`로 멈췄다. 자산 오류 시 발송 단계를 소비하지 않았다. 원자적 파일 교체 실패는 오류만 반환하고 복용 기록과 성공 이미지가 남지 않았다.
- 옵션 없는 기존 출력은 자산을 읽지 않으며 기존 순수 함수를 바꾸지 않았다. 이미지 형식·크기·SHA256 및 네 장의 서로 다른 파일을 검사했다.
- 원본 마스코트를 직접 열어 확인했다. 한 방울·두 방울·미소는 원본 바이트를 그대로 복사했고 글썽 표정만 기존 두 방울 얼굴을 참고해 built-in image_gen으로 만들고 직접 확인했다. 정확한 생성 프롬프트는 `assets/notifications/step1-teary-v1.prompt.txt`다.
- 실제 `.env`·의료 원장·Google Calendar·공공데이터 중계·터널·desk 코드/작업 폴더는 수정하지 않았다.

## 실제 연결에서 확인할 항목

Grok의 실제 채팅 PNG 첨부와 기존 ‘울보 순찰’의 적용은 아직 확인하지 않았다. 적용 프롬프트의 격리된 합성 시연에서 네 장을 실제로 첨부하고, 실제 표시 여부를 도구 JSON 반환 성공과 구분해 보고한다. 기존 구조에 채팅 전달 성공을 확인하는 영속 outbox는 없으므로 최초 결과를 보관하고 첨부만 재시도한다. 앱 아바타 교체·울음 음성·책상친구 화면 변경은 이번 구현에 포함하지 않는다.
