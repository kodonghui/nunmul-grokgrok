# 책상 버튼 백엔드 수신 검증 · 2026-11-01

사용자 승인: 백엔드는 원래 Codex가 수정하고 Grok은 봇 관련 연결만 맡긴다. [명세](desk-receiver.md)를 833e4d4로 먼저 정의했다. desk 장치 worktree는 다른 Codex 채팅이 전담하며 이 작업에서는 해당 소스를 변경하지 않았다.

- TC-DESK-RX-001: 프로필·회차·doseId·medicineId의 정확한 대응, 다른 가족 거부, 특정 약만 복용 확인, Calendar 일부 확인 결과를 검사했다.
- TC-DESK-RX-002: 요청 영수증과 복용 기록의 단일 원자적 저장, 같은 요청 재실행·다른 내용 충돌, 시간 경과/삭제 후 영수증 재실행, 알림 중복 방지를 검사했다.
- TC-DESK-RX-003: 중단·삭제·일정 비우기·일정 변경·SKIPPED/MISSED 거부, 기존 채팅 TAKEN의 시각/출처 보존, 무관한 전역 revision 변경 허용/미래 revision 거부를 검사했다.
- TC-DESK-RX-004: 버튼/수신 시각의 경계, 일정 확인 전 요청 거부, JSON 중복 필드/비유한 수/큰 입력/잘못된 루트, 기존 v3 호환, 수신 중 자동 생성/이관 금지를 검사했다.
- TC-DESK-RX-005: 별도 프로세스의 동일 요청 동시 처리와 두 약의 부분 요청 동시 처리, 저장 실패 시 기록/영수증 롤백, -S -B CLI와 고정된 브리지 해시 예시를 검사했다.

새 수신 테스트23개 + 기존198개 = **py -m unittest 221개, 14.275초, 전부 통과**. 단위 테스트는 가짜 이벤트·합성 약·임시 원장이고 네트워크·실제 키·실제 웹훅을 사용하지 않았다.

별도 오프라인 상호운용 시험에서는 현재 desk worktree의 실제 desk_bridge.py 모듈을 읽기만 하여 parse_schedule/Bridge.button/DeliveryJournal을 실행하고 가짜 시리얼·가짜 HTTP 전달을 새 수신부에 연결했다. 버튼2번→수신1건·영수증1건·recorded=true, 시리얼 P→K→S4→S0을 확인했다. 실제 보드/Google/Grok 네이티브 웹훅을 호출한 시험은 아니다.

현재 수신 도구는 HTTP 서버가 아닌 CLI다. Grok 네이티브 웹훅의 접근 제어, 운영자가 고정한 --profile, 운영자 보안 설정을 전제로 한다. 실제 버튼→Grok 원장→Calendar의 종단 간 검증은 아직 별도다.

공식 Grok Bot 문서에서 Bearer key 전송이 필요함을 확인했고, 현재 desk 전송부의 인증 헤더 보완을 책상친구 Codex 채팅에 직접 전달했다. 노트북 URL/KEY의 보안 전달·설정과 실제401/200·비동기 실행 결과는 그록/책상친구 연결 단계에서 확인한다. 이 작업은 기존 .env·실제 state·공공데이터 중계·원래 사용자 .env.example/.idea/assets를 변경하거나 커밋하지 않았다.
