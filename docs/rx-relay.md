## 계약 · SPEC-RX-RELAY-001

- 노트북 서버는 127.0.0.1에만 바인딩한다. 임시 HTTPS 터널이 그 포트로 전달한다. 터널을 끄면 외부 접근이 끝난다.
- API-RELAY-001 GET /health는 서비스 이름과 정상 여부만 반환한다. 인증정보·키 설정·원장 정보는 내보내지 않는다.
- API-RELAY-002 POST /v1/query는 Authorization: Bearer 인증이 필요하다. 본문은 permit(itemName, 선택 maker), explain(itemSeq), dur(type, itemSeq, pageNo)만 받는다. DUR type은 INTERACTION/AGE/ELDERLY/PREGNANCY, pageNo는1~100이다. 공식 호스트·API 경로·100행 페이지 크기는 서버가 고정한다. URL·경로·serviceKey·임의 파라미터·환자 정보는 받을 수 없다.
- permit/explain 응답은 {"items": [...]}다. DUR 응답은 items·totalCount·pageNo·numOfRows이며 전체 페이지 수집과 품목/내용 검증은 클라이언트가 수행한다. 공식 API 필드 중 필요한 필드만 반환한다. 실패는 기존 {"error":{"code":"...","message":"..."}} 형식이며 공급자 오류 원문은 전달하지 않는다. [OpenAPI](../api/relay.openapi.json) v1.1을 따른다.
- 요청 본문 최대 4096바이트, 이름·제약사 각 200자, itemSeq는 숫자 1~20자다. 인증 토큰은 URL-safe 문자 32~200자다. 동시 처리 최대 8건이다.
- 인증 누락/오류 401, 입력 오류 400, 미지원 경로 404, 미지원 메서드 405, 본문 초과 413, 상류 실패 502, 준비 안 됨/동시 처리 초과 503, 예상 밖 오류 500을 반환한다. 모두 JSON이며 요청·인증 헤더·상류 URL·키·오류 원문을 로그에 적지 않는다.
- 직접 조회의 연결 2초·읽기 10초·일부 오류 1회 재시도는 유지한다. 중계 클라이언트는 연결 2초·읽기 30초로 상류 재시도를 기다린다. 중계 자체 연결 오류·429만 0.5초 뒤 1회 재시도하고, 상류 실패 응답은 다시 중첩 재시도하지 않는다.
- 저장한 클라이언트 설정이 없을 때 PUBLIC_DATA_RELAY_URL 또는 TOKEN 중 하나라도 설정되면 중계 모드다. HTTPS만 허용하며 로컬 테스트의 loopback HTTP는 예외다. 키가 없어도 중계 인증으로 조회할 수 있다. 토큰/주소 누락 또는 중계 실패를 직접 API 호출로 숨기지 않는다. 저장 설정과 두 환경변수가 모두 없으면 기존 직접 모드와 NO_KEY 동작을 유지한다. 저장 설정은 SPEC-RX-RELAY-002의 고정 규칙을 따른다.
- 공식 서비스 키는 노트북의 기존 환경변수/.env에서 읽기만 한다. 별도 중계 토큰은 환경변수 또는 서버의 --token-file로 읽는다. 토큰 파일은 Git에서 제외한 state/에 두고 값은 출력하지 않는다. 그록에는 보안 입력으로 중계 토큰만 전달한다.
- 약 목록·복용 기록·캘린더·사진은 중계 서버가 읽거나 저장하지 않는다. 공식 조회 이름·제약사·품목코드·DUR 유형/페이지 번호만 전송한다. 프로필·동행자·나이·임신 조건을 전송하지 않으며 조건 대조는 봇 컴퓨터에서 한다. 터널 운영자는 HTTPS 연결 경로를 제공한다. 실제 주소·토큰·키는 공개 문서/템플릿에 넣지 않는다.
- 이 추가는 기존 직접 조회·누적 원장·명령의 출력 모양을 바꾸지 않는다. 기존 자료 이관이나 캘린더 변경은 실행하지 않는다.

## 검증 기준

### 실행 사이 설정 유지 · SPEC-RX-RELAY-002

- `python3 tools/relay_config.py save`는 같은 실행 환경의 `PUBLIC_DATA_RELAY_URL`·`PUBLIC_DATA_RELAY_TOKEN`을 모두 검증한 뒤 한 쌍으로 저장한다. 비밀값을 명령 인자에 넣지 않는다. 기존 `.env`는 읽기만 하며 이 저장 명령의 입력은 보안 환경변수 두 개다.
- 저장 위치는 Git에서 제외한 `state/runtime/rx-client/connection.json`이다. 약 원장과 분리하고 원자적으로 교체한다. POSIX에서는 디렉터리0700·파일0600·현재 사용자 소유만 허용한다. Windows에서는 사용자 프로필의 파일 접근 권한을 사용한다. 파일을 첨부·출력·커밋하지 않는다.
- 저장한 한 쌍이 이름 검색·설명·DUR 조회의 공통 설정이다. 작업 디렉터리나 다음 명령의 환경변수가 달라도 저장소 루트에서 같은 설정을 읽는다. 환경변수 일부와 저장값을 섞지 않는다. 비어 있지 않은 환경변수가 저장값과 충돌하면 `RELAY_CONFIG_CONFLICT`로 멈춘다.
- 처음 설정하지 않은 환경은 기존 환경변수/읽기 전용 `.env`와 직접 모드의 `NO_KEY` 계약을 유지한다. 저장 디렉터리가 있는 환경은 중계 모드로 고정한다. 파일 누락·손상·권한 오류·중계 오류가 나면 직접 API로 전환하지 않는다.
- 봇의 이름 검색·설명·DUR 명령에는 `--saved-relay`를 붙인다. 이 옵션은 저장 설정이 없으면 `RELAY_CONFIG_MISSING`으로 중단하므로 초기화로 설정 디렉터리 전체가 사라져도 직접 API로 넘어가지 않는다. 일반 직접 조회용 기존 명령은 호환을 유지한다.
- 같은 설정의 재저장은 변경하지 않는다. 실제 주소나 토큰이 바뀌면 두 값을 같은 보안 실행 환경에 제공하고 `save --replace`로 한 쌍을 명시적으로 교체한다. 잘못된 새 입력이나 쓰기 실패는 이전 한 쌍을 유지한다.
- `python3 tools/relay_config.py status`는 모드·설정 출처·준비 여부만 JSON으로 반환한다. 주소·토큰·인증 헤더·해시·원시 오류는 내보내지 않고 네트워크를 사용하지 않는다. 컴퓨터 초기화로 `state/` 자체가 사라지면 보안 입력 후 다시 설정한다.
- 임시 `rx_env_check.sh`는 공식 실행 경로가 아니다. 정식 Python 명령 자체가 설정을 읽는다. 원격 임시 파일의 원문을 확보하지 않고 코드 검토 완료로 보고하지 않는다.

1. 키 없이 중계 토큰으로 조회하며, 공식 키는 중계 요청·응답에 없다.
2. 인증 오류·임의 주소/경로·추가 개인정보 필드·잘못된 길이는 상류 호출 전에 거부한다.
3. 정상/빈 응답·공급자 실패·네트워크 실패를 구분하고 비밀값을 반사하지 않는다.
4. 단위 테스트는 가짜 HTTP·fixtures만 사용한다. 실제 API/터널 시연은 단위 테스트와 분리한다.
5. 실제 그록에서 동일 이름 검색·그 결과 코드의 설명 조회를 완료해야 그록 연결 성공으로 기록한다. 노트북 자체에서 터널 경유 성공은 원격 그록 성공을 대신하지 않는다.

## 운영과 인계

1. 노트북에서 공식 키가 기존 환경변수 또는 .env에 있는지 값 출력 없이 확인한다. 새 중계 토큰은 secrets.token_urlsafe(32) 등으로 만들고 state/runtime/relay-token.txt에만 저장한다. 기존 .env는 수정하지 않는다.
2. `py tools/rx_relay.py --port 8765 --token-file state/runtime/relay-token.txt`로 실행한다. 토큰을 명령행 인자로 직접 주지 않는다. 기존 서비스가 해당 포트를 쓰면 종료하지 말고 다른 포트를 사용한다.
3. 공식 cloudflared 실행 파일로 해당 loopback 포트만 Quick Tunnel에 연결한다. 실제 호스트·토큰·로그·프로세스 정보는 state/runtime/에만 둔다. 자동 시작 등록은 하지 않는다.
4. 그록에서 최신 main을 받고 오프라인 테스트를 실행한다. 보안 입력의 PUBLIC_DATA_RELAY_TOKEN과 운영자가 알려준 PUBLIC_DATA_RELAY_URL을 같은 실행 환경으로 `python3 tools/relay_config.py save`에 전달한다. 이후 `python3 tools/relay_config.py status`가 configured=true/mode=relay/source=saved인지 확인한다. 설정 뒤 기존 rx_lookup 이름 검색과 실제 반환 품목코드의 --explain을 실행한다. 공식 키를 중계 요청에 보내지 않는다.
   - 저장 뒤 별도 프로세스의 rx_lookup.py·dur_lookup.py가 같은 설정을 자동으로 읽는다. 기존 .env를 자동 편집하지 않는다. 터널 주소/토큰 변경 때만 두 값을 함께 보안 환경에 제공하고 save --replace로 갱신한다. 임시 셸 파일 대신 정식 Python 명령을 사용한다. [전체 전환 프롬프트](grok-bot-relay-setup.md)를 따른다.
   - v3 DUR 지원은 노트북의 기존 Python 중계 프로세스도 최신 코드로 재시작해야 한다. 기록된 실행 파일/명령을 검증한 뒤 해당 프로세스만 재시작한다. 터널·기존 토큰은 유지한다. Python 파일을 pull하는 것만으로 이미 실행 중인 서버 코드가 바뀌지는 않는다.
5. 오류 NO_RELAY_TOKEN은 중계 인증 누락, RELAY_NETWORK_ERROR는 노트북/터널 연결, RELAY_UPSTREAM_*는 노트북 이후 공식 API의 실패다. 실패를 NOT_FOUND나 연결 성공으로 바꾸지 않는다.
6. 대화형 실행은 Ctrl+C로 서버와 터널을 종료한다. 이 작업에서 백그라운드로 실행한 경우 생성된 state/runtime/stop-relay.ps1이 기록된 실행 파일·명령줄을 확인한 뒤 이 작업의 프로세스만 종료한다. 상태 메타데이터의 PID만 보고 다른 프로세스를 종료하지 않는다.

이 작업에서 만든 state/runtime/copy-relay-token.ps1은 중계 토큰을 출력하지 않고 Windows 클립보드에 복사한다. 그록의 보안 입력 카드가 열린 뒤 실행해 그 카드에만 붙여 넣는다. 일반 채팅에는 붙이지 않는다. 클립보드도 민감 정보가 되므로 사용 후 다른 내용을 복사해 비운다. 이 파일들은 실행용 상태이며 공개 저장소에는 포함하지 않는다.

Quick Tunnel은 계정·도메인 없이 임시 주소를 만들며 재시작할 때 호스트가 바뀐다. 종료 후 주소가 동작하지 않고 가용성 보장은 없다. 별도 Bearer 인증을 서버에 두므로 주소만으로 공식 API를 호출할 수 없다. [Cloudflare 공식 안내](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
