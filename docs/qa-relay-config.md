# TASK-RX-RELAY-002 · 조회 중계 설정 유지 검증

근거: 사용자가 2026-11-01 이 Codex 대화에서 “그럼 중계 설정 안 빠지게 백엔드에서 정리해줘. 그록이 만든 rx_env_check.sh도 네가 검토하고, 끝나면 그록한테 보낼 프롬프트 다시 줘.”라고 요청했다. 계약은 [SPEC-RX-RELAY-002](rx-relay.md), 운영 인계는 [전체 전환 프롬프트](grok-bot-relay-setup.md)다.

## 변경과 이유

환경변수를 한 명령에만 전달하면 다음 이름 검색·설명·DUR 호출에서 중계 주소가 빠질 수 있었다. `relay_config.py save`로 검증한 주소·별도 토큰을 비공개 런타임 파일에 한 쌍으로 원자적으로 저장하고 세 조회 경로가 공통으로 읽도록 했다. 환경변수와 저장값이 충돌하면 섞지 않고 중단한다. 봇 명령의 `--saved-relay`는 설정 디렉터리가 전부 사라져도 직접 API로 넘어가지 않게 한다. `.env`와 의료 원장은 수정하지 않는다.

## 직접 확인한 결과

- 수정 후 Windows `py -m unittest`: 243개, 21.960초, 실패0·오류0·건너뜀1. 기존221개에22개를 추가했다.
- 건너뜀은 실제 POSIX 파일 권한 검사1개다. POSIX 소유자·접근 비트의 판단은 모의 메타데이터로 Windows에서도 검증했다. 실제 Linux 파일 권한 검사는 봇 적용 시 `python3 -m unittest`로 확인한다.
- 중계 관련102개를 먼저 실행했을 때 DUR 시험의 대상이 한 품목이라 병용 유형을 조회하지 않는 기존 동작을 확인했다. 시험 대상을 합성 두 품목으로 고쳐 네 유형8건을 검증했고, 관련102개는 실패 없이 끝났다. 이후 테스트 격리 보강과 추가2개를 포함한 전체243개를 통과했다.
- 환경변수 없는 새 프로세스·다른 작업 디렉터리에서도 저장한 설정으로 같은 RelayClient를 선택했다. 가짜 HTTP로 이름 검색·설명·DUR CLI가 같은 주소·인증을 사용하는 것을 확인했다.
- 설정 없는 `--saved-relay`, 누락 파일, JSON 손상·중복 키·비정상 숫자·크기 초과, 환경 충돌, 잘못된 새 주소/토큰, 저장 교체 실패는 안전한 오류로 중단했다. 직접 클라이언트로 전환하지 않았다. 실패한 교체는 기존 파일을 보존했다.
- 같은 설정 재저장은 멱등이며 명시한 `--replace`에서만 한 쌍을 변경했다. 상태·저장·오류 CLI 출력은 비밀값 없는 JSON 한 개다.
- 기존 CLI 테스트도 임시 도구 폴더/설정 루트를 사용하도록 바꿔 운영 중인 `.env`·저장 토큰을 읽지 않게 했다. 단위 테스트는 합성 키·가짜 HTTP·fixtures만 사용했다.
- 새 런타임 경로는 기존 `state/` Git 제외 규칙의 적용을 받는다. 실제 `.env`·약 원장·Calendar·노트북 중계 프로세스·desk worktree는 변경하지 않았다.

## 아직 직접 확인하지 않은 항목

- 사용자 전달 Grok 보고는 세 약의 공식 조회, 등록·Calendar 반영, 음성 삭제가 성공했다고 한다. 이번 설정 유지 수정은 아직 원격 Grok에서 적용 전이며 그 성공 보고를 새 코드의 검증으로 대신하지 않는다.
- `tools/rx_env_check.sh` 원본은 Grok의 별도 클라우드 컴퓨터에만 있고 로컬/추적 저장소에는 없어 직접 코드 검토하지 못했다. 전환 프롬프트는 원본을 검토 완료로 간주하지 않고 실행·수정·커밋을 멈추며 정식 Python 경로로 전환하도록 한다.
- 다음 단계는 Grok에서 최신 main 적용·Linux 테스트·한 쌍 저장·새 실행에서 공개 세 제품 검색·반환 코드의 설명·격리 DUR 확인이다. 삭제한 시연 약을 재등록하거나 실제 원장·캘린더를 바꾸지 않는다.
